# ADR 003 Tablestore tenant partitioning

Decision: use one shared Tablestore table with `PK = TENANT#{tenant_id}`. New events use `SK = EVENT#{event_id}` and store the product and signed quantity delta. A conditional insert is the only write for each event, so retries and concurrent duplicate submissions cannot apply the same event twice without a cross-row transaction. Reads sum matching event deltas over the existing `PRODUCT#{product_id}` row, which acts as the opening-balance snapshot for data created before this change. Rejected alternatives: separate tables per tenant and maintaining a second mutable inventory row on every event. This keeps writes simple and tenant-scoped; the tradeoff is that inventory reads scan tenant event history, so read latency and cost grow with retained events.
